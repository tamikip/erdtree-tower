# English localization

Select **English** in the launcher and set Elden Ring itself to English for a fully English game. The launcher option controls the tower UI and themed textures; native item and dialogue FMGs follow the game's language. Changes take effect after restarting the game. Auto mode reads the Steam installation language for textures; the tower UI text stays Chinese in Auto mode (the in-game language is no longer queried), so select English or Traditional Chinese explicitly for the runtime UI.

Translations are applied only when displaying text. Save keys, item IDs, network messages, and gameplay comparisons retain their original values. Player names are retained. English searches accept localized item, armor, and enemy names alongside Chinese and pinyin.

`official-en.json` is generated from the installed game's English FMGs. Custom catalogs override it. Unknown strings deliberately remain unchanged so coverage audits can identify missing translations.

For compact effect descriptions, use `localization::inline` before drawing the text. It translates the original multiline catalog key before joining lines with spaces in English or Chinese commas in Chinese; replacing newlines before translation prevents multiline keys and patterns from matching.

## Regenerating native text

Use a separate staging directory. `SceneBuilder` arguments are game directory, output directory, input scene-assets directory, mode, and optional mode input:

1. Run `localization-export` to export original language tables and changed Chinese entries.
2. Run `python localization/generate_official_catalog.py <staging>`.
3. Run `python localization/prepare_fmg.py <staging>`.
4. Run `cargo run --release --example localize -- <staging>/fmg-input.json <staging>/fmg-translated.json`.
5. Run `python localization/assemble_fmg.py <staging>`. This rejects untranslated text and changed markup, and fits weapon captions while retaining affix information.
6. Run `english-text <staging>/fmg-english.json` into a second output directory. Copy only its `msg/engus` directory back into `scene-assets/msg/engus` after verification. Do not package the extracted `originals` directory.

For the title and loading tips, pass `scene-builder/title_theme.en.json` to `title_textures.write_dds`, then run `english-theme <texture-directory>`. Copy the verified `menu` output to `scene-assets/locales/en-US/menu`. This replaces only the six theme textures, retaining other UI resources. ME3 and YAFSML load the language package after the base package. Slim distributions reconstruct the English high-quality archive locally and omit unused low-quality overrides.

Build and ship the updated tower DLL together with the English resources and launcher scripts. Do not install just the game DLL.

## Traditional Chinese (zh-TW)

Select **繁體中文 / Traditional Chinese** in the launcher. All tower UI text is converted from the Simplified source at display time with OpenCC's `s2twp` rules (Taiwan standard forms and phrases: 软件→軟體, 内存→記憶體). Tables live in `localization/zh-TW/*.tsv` and are generated by `python localization/generate_zh_tw.py <opencc/dictionary>` from the Apache-2.0 OpenCC dictionaries (notice and license in `localization/zh-TW`). The same script writes `launcher/ui/js/zh-tw.js`, which converts the launcher pages.

In game the conversion happens in `localization::text()`, so save keys, item IDs, network messages and gameplay comparisons keep their Simplified values. Traditional glyphs are not in the shared UI font subset; `generate_zh_tw_fonts.py` cuts a supplement (`TowerSerif-TW-Regular.otf`, `TowerTitleSerif-TW-Bold.otf`, `ui-glyphs-tw.txt`) that is merged only when the language is Traditional, so other languages keep their package size and font atlas. Rerun it after the UI glyph list changes.

Not covered: item names, descriptions and dialogue that the game itself reads from `msg/zhocn`. Those need a `msg/zhotw` copy built on Windows, and stay Simplified until then.
