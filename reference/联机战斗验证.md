# v93 联机战斗验证

这是运行时接入验证版，尚未证明 Seamless 2.0.1 会复制动态生成的敌人。不能作为完整联机版发布。仅战斗节点开放；商店、营地、宝箱和问号事件暂时拦截，避免共享事件标记导致重复奖励或相互消耗。没有生成整合包。

## 已接入

- 房主控制路线，双方调用已有游戏传送入口，各自完成落地和 5 秒准备后才允许刷怪。
- 只有配置为房主的一端调用动态刷怪接口。队友按事件 ID、模型、NPC 参数和加载状态确认敌人复制，不补刷本地替代敌人。复制未确认不发战斗奖励。
- 房主确认胜利并使用传送门后，双方分别打开本地奖励页，按各自职业生成奖励。领取使用已有本地背包、强化、护符效果和契约接口；网络消息不能指定发给哪个角色，也不携带任意物品发放指令。
- 房主等待全员完成契约、适配装备和奖励后才能进入下一战。个人死亡不会直接触发全队重置；需要全员明确报告死亡。无缝的实际复活、观战、房主死亡后的实体保留仍待双人验证。
- 发奖前建立每角色 `party-award` 文件；游戏接口成功且旅程保存成功后才移除。发现未完成记录会停止重发，需要人工核对背包与记录。此保护不是游戏存档与外部文件之间的原子事务，不能宣称断电后自动恢复或绝对不会丢失奖励。

## 配置与启动

双方使用同一版本，先退出游戏。首次验证会使用独立的 `.ertowerparty` 存档与 `seamless-entry/party-runtime` 日志目录，现有 `.ertowercoop` 不会迁移或清空。

房主在 MOD 根目录运行 PowerShell，用实际局域网或 VPN IPv4 替换示例地址：

```powershell
.\New-PartyConfig.ps1 -HostAddress 192.168.1.10
.\Launch-Seamless-Tower.ps1 -PartyConfig .\party-config\host.json
```

把生成的 `guest.json` 私下交给队友，队友运行：

```powershell
.\Launch-Seamless-Tower.ps1 -PartyConfig .\guest.json
```

此配置生成器针对两人测试。配置中的房主必须也是无缝房主，双方仍需按原有方式加入同一个无缝房间。独立 TCP 通道不会替代无缝入房，也不会自动验证 Steam 身份。默认端口为 TCP 47931；使用双方能互通的可信局域网或 VPN，工具不会自动修改防火墙。凭据不能公开，明文通道不适合直接暴露到公网。

双方在大赐福开启旅程、各自选择契约与适配装备，然后由房主选择金色战斗节点。确认：两人同场、只生成一组敌人、两边能看见并攻击同一组敌人、各自领取物品实际到账、一人未领完时房主不能前进。

不开启验证模式时，继续用原来的无缝启动入口，不传 `-PartyConfig`。

## 失败与限制

- 断线、状态超时、地图不一致、领奖中断会暂停同步，不会自动迁移房主或自动续接战斗。保留双方日志后退出验证，再重新组队。
- 出现“未检测到房主敌人的无缝复制”说明目前的动态刷怪方式没有在本次测试中建立可确认的客机实体。需要检查双方日志，再决定改为原生地图预置敌人或适配经核实的复制接口。单靠 TCP 指令不能解决游戏实体复制。
- 启动器若提示现有 `dinput8.dll`，先正常退出正在运行的启动器和游戏；不会覆盖未知代理 DLL。
- 每次验证结束后建议重新启动双方；全队失败后的连续开局尚未验证。不要删除 `party-award` 来盲目重领。

验证记录：核心规则、TCP、双子进程奖励屏障测试通过，原生模块 97 项测试通过，DLL 编译成功。双子进程测试不启动游戏，不能代替真实双人验证。当前机器仍在运行旧游戏进程，未热替换或重启游戏。
