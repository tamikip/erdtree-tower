# 联机独立奖励接入状态

2026-10-10 更新：v93 已将独立 TCP 通道接入可选的战斗验证运行时，调用实际本地发奖、传送和房主刷怪入口。队友是否能接收到无缝复制的动态敌人尚未验证，服务房间仍拦截；不能按完整联机功能发布。详见 `联机战斗验证.md`。不生成整合包。

`src/party_rewards.rs` 为每名队员分别保存 Run、契约、适配装备领取进度、奖励选择和请求序号。同一物品可由两名玩家分别领取；请求只操作由传输层认证的发送者，消息中不能指定另一名领取者。重复消息不再次执行奖励，失败不提交状态。所有队员处理完奖励、契约和装备后才允许房主推进；断线和重载后等待身份重新确认。

`tests/party_rewards.rs` 使用模拟游戏桥测试上述规则。模拟桥不是游戏物品发放，也不证明无缝网络行为。

`src/party_link.rs` 使用独立 TCP 通道，不改写无缝网络包。房主用每名队员单独的凭据分配身份，校验协议版本和旅程编号；拒绝重复连接与客户端伪造房主消息。包含分帧、部分读写、心跳、超时和队列上限。连接建立最多等待 3 秒，必须放在工作线程；游戏任务线程只应消费有界消息队列。当前是明文 TCP，只适用于可信局域网或加密隧道，凭据不能等同于 Steam 身份，也没有自动发现或端口转发功能。

验证：5 个真实 TCP 测试通过，覆盖身份校验、重连、拆包粘包、消息方向和大小限制；另一个测试启动两个独立客户端子进程，分别选契约、处理装备、领取战斗奖励，再由房主推进下一节点。重复领奖请求不重复执行模拟发奖；一人尚未领奖时禁止推进。6 个规则测试和 24 个核心单元测试通过。日志：`work/coop91-green.log`。

复现：`cargo test --locked --offline --manifest-path outputs/erdtree-tower/Cargo.toml --test party_link --test party_link_processes --test party_rewards --lib`。子进程入口显示 ignored 是有意的：父测试会显式调用该入口两次。胜利由测试触发，物品由模拟桥记录，不代表已实现游戏刷怪或真实背包到账。

仍需接入：

1. 将独立通道中的队员与 Seamless 2.0.1 实际会话成员、房主匹配；原版 CSSessionManager 布局不能直接视为无缝接口。
2. 房主控制传送和敌人生成，验证动态敌人确实复制到客机；客机只接收战斗结果，不重复创建敌人。
3. 在各客户端执行 PersonalBridge，限定本地角色；装备到账、持久化收据和网络确认应支持中断恢复，不能把模拟桥直接用于游戏。
4. 适配全队死亡、复活，以及商店、营地、宝箱可能共享的事件标记，避免队员互相消耗机会。
5. 至少两名真实玩家验证选择不同 Buff、同时选择同件装备、先后领奖、断线重连和跨幕。

研究依据：项目固定版本的 fromsoftware-rs 会话源码、现有运行时和兼容性记录。此次 Grok 返回的三个所谓 API 仓库经 GitHub API 核实均为 404，未用作实现依据。未修改运行时的原版在线模式和客机保护检查。
