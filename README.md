- **作用在敌人身上的余烬对成员也生效**：鲜血君王的赐福、永冻吐息、死诞之焰、圣杯余响、荆棘之躯、灵骸迸裂。成员在本机算出要施加的效果（`embers::Strike`：异常积累、按百分比扣血、荆棘反弹，按敌人在名单里的位置指定目标），随每 200 毫秒一次的汇报带上最近 32 条（`Report::strikes`，带序号），房主按序号执行没执行过的（`embers::Fight::apply_remote`）。房主按汇报里成员的余烬核对（`Strike::valid`），没带对应余烬的请求丢弃；荆棘反弹的伤害有上限，对 Boss 照常按最大生命 1% 封顶。
- **余烬只算自己的命中与击倒**：联机时看敌人的 `last_hit_by`，只算本机玩家与本机召唤物的（吸血、癫火、以血还血、噬魂者、灵魂收容、饱食、众灵的盛宴、死诞之焰、出血与冻伤积累都不再吃队友的伤害与击杀）。单人不变。
- **苦难律法「精英成双」联机也生效**：原来联机的敌人一起出，「精英成双 I/II」只加分没效果。现在房主与成员按同一规则（`encounter::may_spawn_paced`、`runtime::member_held`）各自晚一点放出后一只精英的预置实体；房主还在等的精英不算“未绑定”，成员也不等它，开战与胜利照常。
- **苦难律法限时**：成员也有倒计时与超时失血（原来只有房主）。
- **Boss 词条**：成员也显示词条与黄金护盾提示（护盾的时机跟房主：看到 Boss 身上出现护盾效果开始倒计时）；腐败每个人在本机给自己积累；荆棘只把自己（与自己召唤物）打的伤害反弹给自己（原来全队的伤害都反弹给房主）；吸血按全队受到的伤害回血；嫉妒按全队的喝药次数（与律法「嫉妒的世界」相同）。
- **成员的战斗收尾**：成员胜利时也拿 Boss 词条的额外卢恩、也记战斗记录（结算回顾、职业熟练度的精英与 Boss 加成、灵光「30 次 Boss 胜利」都按它算）；全队倒下时房主与成员都记下这场战斗（原来联机的败仗没有记录）。
- **孤狼**：联机成员与联机守卫战也不开放召唤点（原来只有房主与单人检查）。
- **召唤师「群灵」**：联机守卫战胜利时也补回骨灰（守卫战开始时也拍骨灰快照）。
- **竞技场旁的 NPC**：成员开战后也留着（原来只有房主留着）。
- **宝箱爆炸**：联机时不致死（至少留 1 点）。房间里没有战斗胜利，倒下的人等不到救援，全队会卡在这个节点。
- **无缝联机下的重要物品**：灵唤铃、磨刀石等是重要物品，`items()` 在无缝联机下读不到，改用读全部列表的 `loot::count` / `loot::bag_items`：不再每次出发都多发一个灵唤铃；买到的磨刀石记进已获得，商店与奖励不再重复出；事件奖励的“已有不再发”也看得到重要物品。
- 联机协议 42 → 43（汇报多了余烬与敌人侧效果）。

**这次没修（需要实测或 Windows 端的地图）**：
- 联机时在“是男人就下一百层”、风暴城堡、战车事件里倒下的人不会被救起（救援只在战斗胜利后触发，且坠落位置不能直接原地救起）。
- 联机时有人带着石剑钥匙，没钥匙的队员看到的也是上锁的房间（房间布置全队共用）。
- 无缝联机下新开一局时，另一份重要物品列表里上一局的物品可能留着（清背包只清当前列表）。
- 第三幕的英雄石像鬼双人组、事件房里第二波守卫、主题场地、仅单人 Boss、满月女王的联机同步：都需要在 Windows 上补联机实体或重建地图。
- 房主给敌人挂的效果（律法强化、黄金护盾）在成员那边是否同步，影响成员打出的伤害，需要实测。

- 「精英成双」：联机精英战第二只精英在第一只倒下（或半血）后才出现，开战、胜利不卡住。
- 成员能看到 Boss 词条与律法倒计时。

# 新余烬：四个叠层余烬（层数不设上限） · 2026-10-30

层数靠战斗里的事件累积，整局保留（存进 `Run::ember_stacks`，旧存档读进来是 0 层），死了这局结束就清零。只记拿到余烬之后的事件。

| 余烬 | 品质 | 叠层方式 | 每层效果 |
|---|---|---|---|
| 噬魂者 | 史诗 | 击倒得魂：小怪 1、精英 3、Boss 10，每 10 魂一层 | 攻击 +2% |
| 处刑之链 | 史诗 | 每次致命一击一层 | 致命一击伤害 +6%（只对致命一击生效） |
| 屠神者 | 传说 | 每赢一场精英战或 Boss 战一层 | 最大生命 +4%、攻击 +2% |
| 灵魂收容 | 史诗（召唤流） | 召唤物在场时击倒敌人一层 | 召唤物伤害 +3%，受到的伤害 ×0.98（逐层乘算，不会到 0） |

- 层数不设上限：每种余烬在 `SpEffectParam` 里只有两行（`scene-builder/EmberAssets.cs`，9670060/61、70/71、80/81、90/91），运行时（`native/src/embers.rs`）把当前层数的倍率写进没挂着的那一行、先挂新的再摘旧的，正在生效的那一行不改。
- 处刑之链照原版暗杀者赤红匕首的写法，致命一击时给自己挂一个 1 秒的标记（9670005–07），运行时看到标记出现就加一层；增伤照搬短剑护符的写法（`stateInfo` 367 + `throwAttackParamChange`）。
- 修正：最后一只敌人倒下的那一帧就判定胜利，余烬原来看不到这次击倒（Boss 总是最后倒下，噬魂者拿不到 Boss 的 10 魂，饱食、吸血在最后一击上也不触发）；现在胜利那一帧再结算一次。
- 徽记 990017–990020 由 gpt-image-2 生成（`scene-assets/ember-art/emblems-stack.png`）。联机协议 41 → 42（存档多了层数字段）。
- **待实测**：日志 `TOWER_EMBER stack`；背刺、弹反处决后处刑之链是否加层。

# 联机成员的余烬生效（作用在自己与召唤物身上的） · 2026-10-30

原来余烬的战斗结算只在单人与房主那边运行，成员拿到的余烬除了无声处刑和屠神者都不起作用。现在成员也结算（`runtime::member_embers`）：敌人按地图里的预置实体找（与 Boss 血条相同的找法，倒下的也算，用来判断击倒），只作用在自己与自己的召唤物上。

- 成员生效：米凯拉之刃、荷莱·露的再起、古龙之心、以血还血、癫火狂热、噬神之蛇的饱食、四个叠层余烬、仿身泪滴的替身、众灵的盛宴、灵唤铃的号令、双生的灵唤铃。
- 作用在敌人身上的余烬原先只限房主，后来改为成员算出后交给房主执行（见「联机兼容性修正」）。
- 房主在生命归零时就判定胜利，被处决的敌人在成员那边要等动画播完才倒下：成员收到胜利后继续结算到传送门领奖励为止，加的层数同时记进等传送门时暂存的旅程，不会丢。
- 联机时命中与击倒原先不区分是谁打的，后来改为按敌人的 last_hit_by 只算自己的（见「联机兼容性修正」）。

# 修正：联机客机的召唤师胜利后不补回骨灰 · 2026-10-29

召唤师「群灵」（胜利时召唤物还活着，这次召唤不消耗骨灰）在房主和单人上正常，客机上从不补回。原因：客机不在本地生成敌人，没有本地的战斗记录，而“开战时拍骨灰快照、记下用了哪个骨灰”以本地战斗记录为前提，客机从没拍过；收到房主胜利的那段处理里也没有补回这一步。

# 修正：联机时被处决的最后一只敌人成员拿不到卢恩；敌人死后立刻消失 · 2026-10-29

现象：每场最后一只敌人用处决（背刺、弹反处决）打死时，只有房主拿到卢恩，成员视角里这只敌人直接消失、不掉魂。

原因：房主在敌人生命归零时就判定胜利并通知全队；被处决的敌人要等处决动画播完才真正死亡。成员收到胜利后立刻把这场的敌人实体撤下，敌人在成员的游戏里还没走到死亡，卢恩（每个人在自己的游戏里敌人死亡时才发）就发不出来。普通击杀几乎立即死亡，所以只有处决会出问题。

修正（`native/src/runtime.rs` 的 `finish_victory_cleanup`）：成员收到胜利后不再立即撤下敌人。死掉的敌人留着尸体（死亡动画、倒地、掉卢恩都与单人一致，不再“死了立刻消失”），开始传送离开时才一起撤下；收到胜利 8 秒后仍在本机活着的敌人（与房主不同步）单独撤下，免得在选奖励时打人；换了一场联机则作废，不会撤到新一场的敌人。日志 `Party victory cleanup on departure`、`Party victory: removed … enemies still alive locally`。待双客户端实测。

# 修正：换幕后一直发泪滴幼体 · 2026-10-28

进入第二幕（第三幕同理）时会补发一个泪滴幼体：先记下“目标数量 = 当前持有数 + 1”，持有数不够就发一个，达到目标才算发完，否则每 2 秒重试。持有数原来用 `items()` 读，它只读“当前”重要物品列表；无缝联机下（即使只有自己一人）这个列表会切换成联机用的重要物品列表，里面只有圣杯瓶类与露滴的复制品，读不到泪滴幼体，于是发出去的幼体永远“没到账”，每 2 秒再发一个。

- 新增 `loot::held`：普通物品照常累加，重要物品取单机列表与联机列表中较多的那份（复制品两边相同，不会重复计数），再加仓库。泪滴幼体计数、领奖到账核对、按编号计数（磨刀石、石剑钥匙、圣杯露滴等重要物品）与誓约赠礼核对都改用它。
- 保险：同一局同一幕在本次游戏里只发一次泪滴幼体，计数万一再出错也不会一直发；没到账时提示清理背包后重启游戏补发。
- 待实测：无缝联机与纯单机下换幕各只得到一个泪滴幼体。已经多拿的幼体不会收回。

# 修复：F8 调试菜单不能输入中文 · 2026-10-27

调试菜单的筛选框和物品搜索框只收到英文。原因有两层：游戏窗口平时没有输入法上下文，按键直接成了英文字母；就算有，输入法确认的文字要靠系统默认窗口过程转成 `WM_CHAR`，而游戏自己的窗口过程不转发输入法消息，汉字到不了 imgui。

在随项目维护的 hudhook 里补上（`native/vendor/hudhook/src/renderer/ime.rs`，见其 `TOWER_PATCH.md`）：界面需要输入文字时给游戏窗口挂上默认输入法，输完恢复原样（游戏中不会被输入法吞掉按键）；在窗口线程直接读出输入法确认的文字送进 imgui，并去掉结果标记，防止系统再转一份造成重复；只发 `WM_IME_CHAR` 的输入法也支持（含 emoji 这类代理对）；候选框跟着输入框走（`hudhook::set_ime_position`，调试菜单两个输入框已接上）。顺带修掉 `WM_CHAR` 遇到半个代理对时 `unwrap` 崩溃的隐患。全屏独占时输入法候选框可能看不到，建议窗口化或无边框；常用汉字之外的字可能显示为问号（界面字体只收常用字）。

# 修复：召唤师骨灰没死也不退还 · 2026-10-27

召唤师「群灵」（胜利时召唤物还活着，这次召唤不消耗骨灰）原来只在胜利那一刻找“数量为 0 的骨灰”补回 1。两处问题：

- 只写在普通战斗的胜利处理里，三重宝匣、贪欲祭坛等事件房间的守卫战没有；
- 假设召唤时就扣掉骨灰次数。如果游戏是在召唤物离场时才扣，胜利那一刻找不到可补的，随后召唤物被收回、次数变 0，又被每 0.5 秒的清理当成用掉的骨灰删掉——正好是“没死也没还”。

现在两处胜利都走 `keep_summoned_ash`：胜利前 2 秒内召唤物还在也算活着；先补一次，再开 20 秒保护期，期间召唤物离场后才出现的“用掉的骨灰”补回而不是清理（新的一场战斗开始时保护期结束）。两种扣次数的时机都覆盖。日志：`Spirit ash kept after victory`（胜利时补回）、`Spirit ash kept after the summon left`（离场后补回）、`Spirit ash: summon alive at victory, refund waits until it leaves`、`Spirit ash not kept: no living summon at victory`。

# 黄金树之影 DLC 开关 · 2026-10-27

启动参数 `dlc=`（启动器 设置 → 游戏 → 黄金树之影 DLC），下次启动游戏生效，只对单人生效；无缝联机时 DLL 一律按有 DLC 处理，保证双方抽到同样的敌人和奖励（日志 `OPTIONS` 行会注明）。

| 模式 | DLC 敌人 | DLC 武器 | 其他 DLC 物品（防具、护符、法术、骨灰、结晶露滴、战灰） |
|---|---|---|---|
| `full` 有 DLC（默认） | 有 | 有 | 有 |
| `none` 没有 DLC | 不出 | 不出 | 不出 |
| `weapons` 没有 DLC，保留 DLC 武器（实验） | 不出 | 有（含词条版） | 不出 |

依据：同类“全物品商人”模组 Glorious Merchant 提醒没有 DLC 的玩家避开 DLC 物品（媒体转述可能崩溃），论坛说法不一，所以没有 DLC 时默认全部去掉；`weapons` 用来在没买 DLC 的账号上实测 DLC 武器能不能正常用。

- **宿主**：`launcher/Tower.Launcher`（.NET Framework 4.8 WinForms + WebView2，Windows 10/11 自带框架）。开始游戏调用同一个 `Start-Tower.ps1`（单人/无缝联机，隐藏控制台；失败原因经新增的 `-ErrorFile` 参数带回界面）；首次启动从 Steam 库自动找游戏目录；游戏运行时拒绝更新；同时只允许一个启动器。
- **更新方式**：按内容寻址。每个版本在 GitHub Release 上传两个文件：`tower-release.json`（这一版的完整文件清单，以及每个文件内容在哪个版本的数据包、偏移、长度）和 `tower-pack-v<N>.bin`（只含以前所有版本都没有的文件内容，逐个压缩）。启动器读最新清单，与本地文件哈希逐个比较，只用 HTTP Range 分段下载缺的那几段（GitHub 的下载地址返回 206，已实测）。跳过多个版本、半途中断、文件损坏都归结为同一个“补齐差异”计划，不需要版本链。
- **安全**：清单里的路径必须在安装目录内（拒绝 `..`、绝对路径、反斜杠、更新器自己的目录与 `tower-install.json`/`GamePath.txt`）；下载的数据解压后校验 SHA-256 才进暂存区；安装时先写进度记录，每个被替换或删除的文件先挪进本次的备份目录，失败即还原，进程被强杀则下次启动还原。跳转由更新器自己跟随并保留 Range，拒绝从 https 跳到 http。
- **代码**：`launcher/Tower.Update`（更新引擎，netstandard2.0），`launcher/Tower.Update.Tests`（端到端测试：首装、只下变化的文件、跳版本、损坏修复、安装中途失败回滚、强杀后恢复、模拟 GitHub 跳转与分段下载、路径安全、相邻数据合并请求、校验时忽略哈希缓存），`distribution/release_pack.py`（生成清单与数据包，`tests/test_release_pack.py`）。

发版：在 Windows 上照常运行 `python distribution/package.py`，它会额外编译启动器（需要 .NET SDK）、放进包里，并从最新 GitHub Release 取上一版清单生成增量数据。**第一次带启动器的版本**用 `--first-release`（数据包包含全部文件）。把输出的 ZIP、`release-v<N>/tower-release.json`、`release-v<N>/tower-pack-v<N>.bin` 上传到标签为 `v<N>` 的 Release 并设为 latest；**不要删除旧 Release**，新清单里没变的文件仍然指向旧版本的数据包。可用 `--notes <文件>` 附带更新说明。发版前可以把环境变量 `ERDTREE_TOWER_UPDATE_SOURCE` 指向本地目录（`<目录>/latest/tower-release.json` 与 `<目录>/v<N>/tower-pack-v<N>.bin`）先自测。

**国内镜像（阿里云 OSS）**：启动器有两条下载线路，国内镜像与 GitHub。检查更新时同时问两条，取版本最高的一份（同版本按设置里「下载线路」的优先顺序，默认国内镜像），所以镜像忘了传新版本也不会让玩家错过更新；数据下载失败时自动换另一条。镜像地址在 `launcher/sources.json`，现为 `https://eldenring-mods-hz.oss-cn-hangzhou.aliyuncs.com/releases`；这个文件随模组发布，以后改地址也是发个新版本。

3. 发版时 `python distribution/package.py --upload`：打包后把 `dist/mirror-v<N>/releases`（与 GitHub 下载地址同样的目录结构）按顺序传上去（数据包与版本清单先传，`latest` 最后），再自动检查。上传中断可以单独重跑 `python distribution/upload_mirror.py dist/mirror-v<N>`，同样内容覆盖不会出问题（`tests/test_upload_mirror.py`）。不要给存储桶开「禁止覆盖」，`latest` 每次都要覆盖；旧版本的 `download/v<旧版本>/` 不要删，和 GitHub 一样，没变的文件仍然指向旧数据包。
4. 检查脚本也可以单独用：`python distribution/check_mirror.py <线路地址> --expect <N>` 读最新清单，并对每个数据包做一次分段下载与 SHA-256 校验，有问题会说明是没传、版本不对还是不支持分段（`tests/test_check_mirror.py`）。GitHub 线路也能这样检查：`python distribution/check_mirror.py https://github.com/tamikip/erdtree-tower/releases`。

注意：WebView2 界面、DPI 缩放、启动脚本调用和 Windows 下的文件替换只在 Linux 上编译通过，尚未在 Windows 实机运行；国内镜像的读取与分段下载逻辑有测试（`Tower.Update.Tests` 共 18 项：版本落后的镜像、失败线路换下一条、卡住的线路不拖慢检查、全部连不上时逐条说明原因），真实存储桶在第一次上传后由 `upload_mirror.py` 自动检查分段下载。

# Boss 血条名字特效（实验）· 2026-10-27

HUD 里 Boss 血条的名字（`BossList.Item_N_0.Name.Text`，最多同时三条）加上动态效果，与屏幕上方的词条行、Boss 身上的光效颜色一致：

- **词条**：名字前缀“狂暴的·黄金律法的 …”里每个词条用自己的颜色（`fancy_text::affix_style` 的主色），在主色与亮色之间缓慢流动；“·”为灰色。只有空格前每一段都是已知词条时才上色，Boss 名里自带的“·”（如“荷莱·露”）不受影响。
- **Boss 名**：在原本颜色与金色之间沿字缓慢流动，一道白金扫光从字上扫过（宽峰，最多提亮到九成）。
- **整行**：细金边、向上飘动的光焰与随呼吸明暗的外圈柔光（光焰与柔光用第一个词条的颜色，没有词条时为暖金色）。不改字体、字号、位置，伤害数字不动。

实现：HUD 文件 `01_000_fe.gfx` 没有主时间轴类，效果挂在每条血条红色血量条（`Current`，类 `_01_000_FE_fla.BossFE_Bar_Ani_40`）的构造函数上，每帧向上两层找到名字。源码 `scene-builder/native_boss_bar_glow.py`（复用 `native_name_glow.py` 的结构校验）：只有脚本块改变、其余 386 个脚本反编译结果不变，记录在 `reference/native-boss-bar-glow-build.json`；`tests/test_native_boss_bar_glow.py` 检查词条名、顺序、颜色与 `src/boss_affixes.rs`、`fancy_text.rs` 一致。由用户提供的原版 HUD 文件构建，放在 `scene-assets/menu/01_000_fe.gfx`。

注意：这会替换整个游戏内 HUD 界面文件，与其他修改 HUD 的模组不能直接叠加；如果游戏每帧都重写名字，特效可能不显示或闪烁，需要实机确认。

# 原生装备名品质特效：传说为灾厄“燃金”式（实验）· 2026-10-27

其他品质也有特效，品质越低越少（原生详情页与自绘界面一致）：

| 品质 | 字身 | 描边与光晕 | 扫光 | 闪光 | 星光与字后光 |
|---|---|---|---|---|---|
| 传说 | 暗红紫 | 金描边 + 向上火焰 | 有 | 约 3.3 秒一次 | 星光密，字后金光 |
| 史诗 | 暗紫 | 紫描边 + 两道环绕旋转的紫影（灾厄 CosmicPurple） | 有 | 无 | 星光稀疏，字后淡紫光 |
| 稀有 | 蓝色缓慢流动 | 随呼吸明暗的柔和蓝光 | 有，较慢 | 无 | 无 |
| 普通 | 原色 | 无 | 偶尔一道淡扫光 | 无 | 无 |

原生详情页按“传说·／史诗·／稀有·／普通·”前缀的字符编码识别品质，换到另一种品质时重建滤镜，换到没有品质前缀的物品时恢复原样。

自绘界面（奖励卡、奖励详情、构筑面板）见 `fancy_text::quality_name`：传说为 `auric`（火焰副本与 8 方向描边先画、暗红紫字身后画、窄扫光只落在字上、闪光、上升旋转的十字星光、字后柔和的横向光带）；其他品质由 `glyph_pass` 按档位组合光晕、描边、字身与扫光，史诗另加字后光与稀疏星光。补正属性与防具类型保留各自的颜色，体现在描边上（如力气红描边、灵巧绿描边，全属性五色轮转）；其他品质不变。

武器、防具详情页的传说装备名（识别“传说·”前缀）改为参照泰拉瑞亚灾厄模组的稀有度名字做法：灾厄并不靠粒子，而是把同一行字叠画多层做亮色描边与光晕，再加一道窄扫光与偶发闪光。这里用 Scaleform 的文字滤镜与加色混合实现：

- **字身**：逐字配色并缓慢流动。默认“燃金”风格为暗金字身（灾厄的招牌：暗色字身 + 发光描边）；构建时 `--style gold` 改为亮金字身配暗琥珀描边。
- **扫光**：亮度按 ((sin(kx − vt) + 1) / 2) 的 n 次方取峰值，只改字的颜色，字间空隙不发白（早先版本另画了一条斜向亮带，扫过空隙也会发白，已去掉）。普通、稀有字身本来就亮，用 120 次方的窄峰；史诗、传说字身暗，窄峰会让单个字从暗色突然跳亮，改用 24 次方的宽峰（约两个字宽、边缘渐变），最多只提亮到四成多。
- **闪光**（传说）：约每 2 秒有六成机会亮一下（平均约 3.3 秒一次），0.5 秒内渐亮渐暗，主要提亮描边与热光，字身只略微泛白，不抖动。
- **文字滤镜**（接在原有滤镜之后）：金色描边、内层热光、两层向上偏移的投影组成火焰（一层快速闪动，一层左右摆动），外层泛光随呼吸明暗。燃金风格的字身为暗红紫（灾厄燃金的 77,0,33，在相近色间缓慢流动）。
- **字后与字前**：加色混合的椭圆金光；星光照灾厄 CosmicPurple 的做法，位置固定、轮流亮起、上升并旋转的十字光，约每 20 像素宽一颗。旧版的十字星芒、下划线流星、火星与扩散光环已移除。
- 不改属性、字体或字号；切换到非传说装备时清除装饰并恢复原有颜色与滤镜。仅覆盖两份 `scene-assets/menu/02_05*.gfx`，商店左侧列表和道具详情不受影响。它与爬塔自绘界面的动态文字是两套实现。

源码为 `scene-builder/native_name_glow.py`，构建需游戏 GFX 与 JPEXS FFDec 26.4.0：`--ffdec`、`--original`、`--output`，可选 `--style auric|gold`、`--java`。`--rebase` 允许以上一版已打补丁的菜单为输入，先剥离旧的名字特效再写入新的（本版即由仓库内上一版菜单重建）。构建会检查只有脚本块（DoABC）改变、其余脚本反编译结果不变，SHA-256 记录在 `reference/native-name-glow-build.json`（`originalSha256` 为原版菜单，`baseSha256` 为本次输入）。与其他修改相同菜单文件的 UI 模组不能直接叠加。已通过编译与结构校验；效果按 Pillow 近似模拟预览过，尚未实机确认（尤其是加色混合、渐变填充与 `getCharBoundaries` 在 Scaleform 中的表现）。

# 刷怪方式 · 2026-10-26

## 这版的交互

- 点击篝火、宝箱、商店节点后传送至对应房间，使用游戏自己的交互键或手柄提示，不再弹出自定义 NPC 面板。
